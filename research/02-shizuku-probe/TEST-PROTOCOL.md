# Эксперимент 02 — APK и Shizuku UserService

Цель: на Xiaomi 14T Pro / Android 16 проверить реальные границы обычного APK и Shizuku UserService при активном сотовом звонке без громкой связи.

## Состояния

- `APP`: `AudioRecord` в процессе APK, UID приложения.
- `SHELL`: тот же код в Shizuku UserService, ожидаемый UID 2000 при запуске Shizuku через ADB.
- `RECORD_AUDIO` и разрешение Shizuku выдаются вручную на телефоне.
- Это диагностический APK, не звонилка и не автоматическая запись звонков.

## Перед тестом

1. Подключить телефон к ADB и убедиться, что Shizuku запущен через ADB, не root.
2. Установить APK из GitHub Actions.
3. Открыть probe и выдать `RECORD_AUDIO`.
4. Нажать `Запросить Shizuku`, подтвердить доступ.
5. Нажать `Подключить UserService`; в логе должна быть строка `UserService connected: uid=2000`.
6. Совершить обычный входящий или исходящий вызов через Google Phone, оставить earpiece, выключить громкую связь.

## Запись

Во время разговора отдельно нажать:

1. `Обычный UID: запись 10 секунд`.
2. После завершения нажать `Shell UID: запись 10 секунд`.

Для каждого запуска сохранить лог экрана и WAV. Не запускать два рекордера одновременно.

## Проверка

Извлечь:

- APK app-specific WAV через `adb shell run-as com.ddmsngr.mydialerprobe cat ...` или Android Studio Device Explorer.
- Shell WAV: `/sdcard/Download/MyDialerProbe/shell-voice-call.wav`.

Для каждого файла проверить заголовок, длительность, ненулевые сэмплы, L/R корреляцию и разборчивость обоих голосов на известном речевом тесте. Ненулевой файл без прослушивания не считается доказательством записи обеих сторон.

## Критерии

- `APP` отказал, а `SHELL` записал две разборчивые стороны: Shizuku UserService технически даёт нужную UID-позицию для этого аудиопути, но автоматизация и работа при блокировке экрана ещё не доказаны.
- Оба отказали: Shizuku не решает задачу на этой прошивке через данный API.
- `SHELL` создал WAV, но один голос отсутствует или неразборчив: цель не достигнута.
- Любой результат фиксировать с UID, exception, `AudioRecord state`, размером файла и состоянием звонка.

Рабочая версия звонилки теперь находится в корне репозитория; этот документ сохраняет только результаты диагностического probe.

## Фактический результат — 25.11.2026

- Тест на исходящем вызове `CallTC@85`: Telecom зафиксировал `TYPE_EARPIECE` в `12:47:03` и `SET_ACTIVE` в `12:47:14`; приложение probe было на переднем плане. `RECORD_AUDIO` выдан, Shizuku 13.5.4 запущен через ADB, UserService подключён как UID 2000.
- При запуске записи APP интерфейс показал `APP AudioRecord state=0`. При запуске SHELL показал `SHELL AudioRecord state=0`. В обоих случаях `AudioRecord` остался неинициализированным (`STATE_UNINITIALIZED`); WAV не создан. `/sdcard/Download/MyDialerProbe` отсутствует, app-specific запись также отсутствует.
- Итог: обе попытки записи отказали до чтения аудио. Речь сторон не записана; это не тест разборчивости. Причину отказа по системным логам установить не удалось. Требуется отдельная диагностика конфигурации/доступности `VOICE_CALL` на этой прошивке; не считать обычный UID и Shizuku доказанными рабочими путями.
